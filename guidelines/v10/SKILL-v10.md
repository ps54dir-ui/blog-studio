# Content Review Skill v10

콘텐츠 생성 완료 후 자동 검수 + 발행 전 검수를 하나의 흐름으로 처리하는 스킬.

검수 항목 전체는 `checklist-v9.md`에 정의되어 있다. 이 SKILL.md는 검수 흐름과 판단 기준을 담는다.
v10 변경사항: 블로그 검수 흐름에 C-08(배치 판단 기준 충족) + C-08A/B/C(SEO/GEO/AEO) 반영. C-10 삭제(C-08A에 통합). 블로그 3개 플랫폼 개별 검수 분기 추가.
v9 변경사항: 스레드 8유형 체계 반영 (checklist C-05~05H 연동).

---

## 검수 실행 조건

### 자동 트리거 (사용자 요청 없이 실행)
- Master JSON 생성이 완료된 직후
- 콘텐츠 생성 작업의 마지막 단계가 끝났다고 판단될 때

### 수동 트리거 (사용자 요청 시 실행)
- "검수해줘" / "발행 전 확인" / "올리기 전에 봐줘" / "체크해줘" / "오류 없나 확인"
- 특정 채널 명시: "블로그 올리기 전 확인" / "틱톡 업로드 전에 봐줘"

---

## 검수 실행 흐름

### STEP 1 — 대상 파악

생성된 콘텐츠에서 다음을 확인한다:
- 포함된 채널 목록 (숏폼 / 블로그 / 카페 / 스레드 등)
- 원고의 분야 (의료 / 건강기능식품 / 화장품 / 금융·투자 / 일반)
- 광고·협찬 여부 (사용자가 언급했거나 원고에 경제적 이해관계 구조가 있는지)

### STEP 2 — 카테고리별 검수 실행

checklist.md의 기준에 따라, 아래 순서로 카테고리를 실행한다.

#### [F] 형식 체크 — 항상 실행
체크리스트의 F-01 ~ F-11을 순서대로 확인한다.
판단 기준: 생성된 콘텐츠 텍스트를 직접 읽어서 항목별로 있다/없다를 확인.

#### [C] 채널별 규칙 체크 — 해당 채널만 실행
STEP 1에서 확인한 채널에 해당하는 항목만 실행한다.
예) 블로그만 생성했으면 C-08 + 해당 플랫폼 C-08A/B/C + C-09만 확인. 미들폼이 포함됐으면 C-13도 함께 확인.

**블로그 검수 분기:**
- 네이버 블로그 포함 시: C-08(공통) + C-08A(네이버 SEO/GEO/AEO) + C-09(서식 가이드)
- 티스토리 포함 시: C-08(공통) + C-08B(티스토리 SEO/GEO/AEO)
- 워드프레스 포함 시: C-08(공통) + C-08C(워드프레스 SEO/GEO/AEO)

#### [L] 법적 체크 — 해당 분야만 실행, 웹 검색 연계
STEP 1에서 감지한 분야에 해당하는 항목만 실행한다.

**중요: L 카테고리는 아래 원칙을 따른다**
- 의료·건강기능식품·화장품·금융·투자 분야가 감지되면 → 웹 검색 먼저 실행
- 검수 기준: checklist.md의 내용이 아닌 **웹 검색 결과를 우선**
- 법령은 수시로 바뀌므로 지침에 적힌 내용과 달라도 검색 결과를 따른다
- **폴백 (웹 검색 불가 시)**: checklist.md의 L 항목 기준을 임시 적용하되, 리포트에 "⚠️ 웹 검색 미실행 — checklist 기준 임시 적용. 발행 전 현행 법령 직접 확인 필수" 경고를 반드시 포함한다
- 웹 검색 쿼리 예시:
  - 의료: "의료광고 사전심의 2025 네이버블로그 인스타그램"
  - 건강기능식품: "건강기능식품 체험기 광고 식품표시광고법 2025"
  - 화장품: "기능성화장품 광고 사전심사 2025"
  - 금융·투자: "유사투자자문업 SNS 유튜브 자본시장법 2025"
  - 광고 표시: "추천보증 심사지침 광고표시 위치 2024 개정"

#### [Q] 품질 체크 — 항상 실행
Q-01 ~ Q-04를 확인한다.
AI 냄새 금지 표현은 원고 전문을 스캔해서 있으면 해당 표현과 위치를 리포트에 표시.

#### [A] 오디오 체크 — 영상 콘텐츠 포함 시만 실행
숏폼 공통 에셋 또는 미들폼이 포함된 경우에만 실행.

### STEP 3 — 검수 결과 리포트 출력

아래 형식으로 출력한다. 통과 항목은 생략하고 **문제 항목만** 보고한다.

```

🔍 콘텐츠 검수 결과
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━
검수 대상: [채널 목록]
분야: [일반 / 의료 / 건강기능식품 / 화장품 / 금융·투자]
```

### STEP 4 — 수정 실행 (요청 시)

사용자가 "수정해줘" 또는 특정 항목 수정을 요청하면:
1. 🚨 즉시 수정 필요 항목부터 처리
2. ⚠️ 확인 필요 항목은 사용자 의도 확인 후 처리
3. 수정 완료 후 해당 항목만 재검수 실행
4. 완료 선언 기준:
   - 🚨 항목이 모두 해소된 경우 → "발행 준비 완료" 선언
   - 🚨 항목이 미수정 상태로 남은 경우 → "⚠️ 미수정 위험 항목 N건 포함 — 발행 전 반드시 확인 필요" 경고 포함 선언
   - ⚠️ 항목만 남은 경우 → "발행 준비 완료 (확인 권장 항목 N건 남음)" 선언

## 판단 기준 — 오류 심각도 분류

### 🚨 즉시 수정 필요
- 법적 위반 가능성이 있는 항목 (L 카테고리)
- 파이프라인 파싱 오류 유발 항목 (F-03, F-04, F-05, F-08, F-09, F-10, F-11)
- 발행 후 플랫폼 제재 위험 항목 (워터마크 영상, 금지 해시태그, 브랜드 언급)

### ⚠️ 확인 필요
- 누락이지만 발행 자체를 막지는 않는 항목 (면책 고지, AI 표시 문구)
- 채널 규칙 미적용 (발행 순서, 스레드 유형 구분·배분)
- 오디오 라이선스 미명시
- 블로그 시각 쉼 간격 초과 (권장이므로 ⚠️, 대표이미지 누락은 🚨)
- 블로그 SEO/GEO/AEO 구조 미충족 (C-08A/B/C — 발행은 가능하나 검색 노출에 영향)

### ✅ 통과
- 항목이 명확히 충족된 경우
- 해당 없는 항목 (채널이 없거나 분야가 아닌 경우)

## 검수 실행 시 주의사항

1. **모든 항목을 나열하지 않는다** — 통과 항목은 숫자만 집계. 문제 항목만 상세 출력.
2. **법적 항목은 웹 검색 없이 판단하지 않는다** — 검색 결과 없으면 "확인 필요 (검색 필요)" 표시.
3. **한 번에 전체 검수** — 카테고리를 나눠서 여러 번 보고하지 않는다. 1회 실행 → 1개 리포트.
4. **수정 요청 시 즉시 처리** — 리포트 후 "수정해줘"가 오면 설명 없이 바로 수정 실행.
5. **자동 트리거 시 별도 안내 없이 실행** — "검수를 실행하겠습니다" 같은 예고 문구 없이 리포트만 출력.
